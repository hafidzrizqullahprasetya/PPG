\chapter{Dasar Teori}

\section{Project Third Person dan Setup Level Baru}
Project praktikum kali ini saya buat dari template \textbf{Third Person} pada kategori Games di Unreal Project Browser. Template IntroToUnreal yang dipakai pada pertemuan 2 sengaja ditinggalkan karena ada bug pada 3D model karakter yang bisa menghambat materi Rigging/Retargeting berikutnya \cite{modul3}. Project Name saya isi dengan format \textbf{NAMA\_NIU\_PPG}, sehingga project saya bernama \texttt{HAFIDZ\_535493\_PPG}.

Berbeda dari pertemuan 2 yang langsung membuka tutorial interaktif, project Third Person dimulai dari level contoh yang relatif kosong. Karena itu modul meminta saya menyiapkan level sendiri: membuat folder \textbf{Maps} di Content Drawer, lalu membuat file \textbf{Level} baru di dalamnya lewat klik kanan \cite{modul3}. Level di Unreal adalah wadah berisi semua actor (mesh, light, camera, Player Start) yang tampil di scene, dan setiap Level tersimpan sebagai file \texttt{.umap} \cite{epic-levels}.

Langkah berikutnya adalah pencahayaan dasar. Saya membuka Level baru, klik menu \textbf{Windows} di kiri atas editor, lalu membuka \textbf{Env.\ Light Mixer}. Di window tersebut saya menekan semua tombol \textbf{Create} (Sky Light, Directional Light, Sky Atmosphere, Volumetric Cloud, Exponential Height Fog) supaya level langsung punya setup pencahayaan lingkungan yang otomatis dan realistis \cite{modul3}.

Terakhir, saya menambahkan terrain dan titik spawn. Lewat \textbf{Landscape Mode} saya membuat landscape berukuran \textbf{7x7 Quads, 8x8 Component, Section 1x1}, mengganti gamemode ke \textbf{BP\_FirstPersonGameMode}, lalu menaruh \textbf{Player Start} ke Level \cite{modul3}. Player Start adalah actor kecil berbentuk bendera yang menandai posisi dan arah spawn karakter saat game dijalankan, dan ikonnya berada di sebelah kiri tombol Play pada toolbar atas \cite{epic-place}.

\section{Blueprint, Event BeginPlay, dan Event Tick}
Sebelum menulis logika, saya menyiapkan folder \textbf{Blueprints} sebagai tempat semua file kode. File Blueprint memakai prefix \textbf{BP\_} sesuai konvensi penamaan resmi Epic Games \cite{epic-naming}. Blueprint yang saya buat bernama \texttt{BP\_Box}. Karena Blueprint pada dasarnya kosong (cuma titik pivot), saya menekan tombol \textbf{+ Add} di panel Components lalu menambahkan komponen \textbf{Cube} supaya Blueprint punya wujud kotak saat di-spawn ke map \cite{modul3}.

Kode di Unreal Engine 5 tidak bisa jalan tanpa \textbf{event} sebagai pemicu. Dua event bawaan yang selalu ada di tab \textbf{Event Graph} adalah \textbf{Event BeginPlay} yang dieksekusi satu kali saat game atau objek dimulai, dan \textbf{Event Tick} yang dieksekusi terus-menerus setiap frame \cite{modul3}. Cara membuktikan graph saya jalan cukup sederhana: Blueprint di-drag and drop ke dalam level, lalu node \textbf{Print String} dipasang. Kalau teks debug muncul di layar saat Play, berarti kode di Event Graph berhasil dieksekusi \cite{modul3,epic-unreal}.

Actor sendiri adalah objek dasar yang bisa ditempatkan di level, sedangkan Pawn/Character adalah actor yang bisa dikendalikan input pemain \cite{epic-actors}. Pemahaman ini membantu saya membaca hubungan antara BP\_Box yang saya buat dan karakter Third Person yang dipakai untuk menguji input keyboard nantinya.

\section{Variabel di Blueprint}
Variabel di Blueprint menyimpan data yang dipakai logika. Pilihannya banyak, mulai dari tipe primitif seperti Boolean, Integer, Float, String, dan Vector, sampai tipe tambahan seperti \textbf{Transform} yang otomatis membungkus tiga variabel sekaligus (Location, Rotation, Scale), \textbf{Enum}, dan \textbf{user defined class} \cite{modul3,epic-variables}. Variabel baru saya buat dari panel \textbf{My Blueprint} dengan mengklik ikon \textbf{(+)}, lalu tipe datanya dipilih dari daftar drop-down. Instruksi modul meminta saya menambahkan variabel bertipe \textbf{Boolean} pada \texttt{BP\_Box} sebagai bahan percobaan Branch \cite{modul3}.

Selain variabel tunggal, modul juga memperkenalkan \textbf{Struct Variable}. Struct adalah child Blueprint yang menampung beberapa variabel beda jenis dalam satu wadah, mirip List atau Dictionary kompleks di Python \cite{modul3}. Materi ini baru sekadar pengenalan dan dijanjikan dibahas lebih dalam pada pertemuan berikutnya, jadi saya cukup memahami idenya: satu Struct bisa menyimpan String, Integer, dan Boolean sekaligus dalam satu paket.

\section{Branch dan Kontrol Alur}
Node baru ditambahkan dengan \textbf{klik kanan} pada area kosong Event Graph lalu mengetik kata kunci seperti ``if'', ``get \textless nama\_variabel\textgreater'', ``set \textless nama\_variabel\textgreater'', atau ``print string'' \cite{modul3}. Navigasi kanvasnya memakai klik kanan yang ditahan sambil menggerakkan mouse (panning), supaya graph yang panjang tetap gampang dijelajahi.

Node \textbf{Branch} adalah padanan \textit{if} pada pseudo-code. Node ini punya satu pin eksekusi masuk, satu pin kondisi bertipe Boolean, dan dua pin eksekusi keluar yaitu \textbf{True} dan \textbf{False} \cite{modul3,epic-flow}. Alur cuma lewat ke salah satu cabang sesuai nilai kondisinya.

Contoh paling sederhana di modul memakai \textbf{Event Tick} yang disambung ke logika penekanan tombol. Saya mengetik ``keyboard'' pada menu tambah node untuk memunculkan \textbf{Keyboard R} dari kategori Input Events \cite{epic-input}. Pin Pressed/Released dari node tersebut dipakai untuk mengubah variabel Boolean lewat node \textbf{Set}, lalu variabel itu dibaca lewat node \textbf{Get} dan dimasukkan ke pin kondisi Branch. Node \textbf{Not Boolean} saya pakai untuk membalik nilai logika. Dari pin True dan False, dua kabel eksekusi saya sambungkan ke dua node \textbf{Print String} berbeda, sehingga teks yang tercetak di layar berganti tergantung tombol R sedang ditekan atau tidak \cite{modul3}.

Di luar Branch, Unreal masih punya node flow control lain: \textbf{Switch} (satu input, banyak output Case untuk mencocokkan nilai), \textbf{Do Once} (eksekusi cuma sekali sampai di-reset), \textbf{Flip Flop} (output A dan B aktif bergantian), dan \textbf{Gate} (pintu Open/Close/Toggle yang mengatur apakah alur boleh lewat) \cite{modul3,epic-flow}. Keempatnya ditandai opsional dan boleh dipelajari mandiri kalau waktu praktikum tidak cukup.

\section{Penerapan If/Else Real-Time dan Konvensi Penamaan}
Tugas praktikum meminta saya mengaplikasikan if/else untuk mengubah scale, rotasi, atau lokasi mesh \textbf{secara real-time} lewat kode pada Event Tick \texttt{BP\_Box}. Caranya: saya menambahkan variabel float bernama \textbf{scale target} dengan default value \textbf{0.1}, lalu Event Tick dipakai untuk menggeser nilai Scale mesh menuju target tersebut lewat node matematika seperti pengurangan atau Lerp \cite{modul3}. Satu trik penting dari modul: \textbf{klik kanan pada pin konektor} operasi bilangan untuk mengonversi tipe data (misalnya Vector ke Float), supaya operasi matematikanya tidak error merah dan bisa jalan \cite{modul3}.

Modul memberi catatan jujur bahwa cara ini \textbf{bukan best practice} dan cuma untuk keperluan praktikum. Mengubah transformasi di dalam Event Tick tanpa Delta Time atau Timeline membuat pergerakan tidak konsisten di beda frame rate dan membebani performa \cite{modul3}. Menjalankan game dari editor sendiri bisa dilakukan lewat tombol Play atau menjalankan project standalone untuk pengujian yang lebih bersih \cite{epic-running}.

Supaya project tetap rapi, saya mengikuti konvensi penamaan resmi Epic: prefix \texttt{BP\_} untuk Blueprint, \texttt{M\_} untuk Material, \texttt{T\_} untuk Texture, dan seterusnya \cite{epic-naming}. Kebiasaan kecil ini membuat aset gampang dicari saat project membesar.

\chapter{Kesimpulan}
Dari praktikum Pertemuan 3 Variable \& Condition, saya simpulkan bahwa template Third Person adalah titik awal yang tepat untuk materi logika karena bebas dari bug rigging IntroToUnreal. Level kerja saya siapkan sendiri dari folder Maps, file Level baru, pencahayaan Env.\ Light Mixer, Landscape 7x7, dan Player Start sebagai titik spawn.

Saya juga memahami alur kerja Blueprint: file beraudit prefix \texttt{BP\_} dengan komponen Cube, event BeginPlay yang jalan sekali dan Event Tick yang jalan tiap frame, serta variabel Boolean yang saya buat dari panel My Blueprint. Node Branch terbukti berfungsi sebagai \textit{if} dengan dua cabang True/False, dan input Keyboard R lengkap dengan Set/Get serta Not Boolean membuat teks debug berganti sesuai tombol yang saya tekan.

Untuk tugasnya, variabel float \textit{scale target} 0.1 dan konversi pin konektor ke float membuat Scale mesh bergeser real-time tanpa error. Saya mencatat cara ini bukan best practice tanpa Delta Time atau Timeline, tapi cukup untuk membuktikan konsep if/else di Blueprint. Node Switch, Do Once, Flip Flop, dan Gate saya pelajari mandiri sebagai bekal flow control berikutnya.
